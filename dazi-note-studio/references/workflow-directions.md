# 从工作流提取卖点与场景

来源：[DuMate爆款工作流测试集 副本](https://my.feishu.cn/wiki/Nm6JwgH4giarfika7KNc9Klonkg)，2026-09-15读取12类工作流及6张嵌入成果图。它是选题/测试方向资料；静态截图不能证明持续监控、自动连接或所有动作当前可用。正式能力另对照核心功能文档，动态信息按本篇需要核实。

不要把整行卖点全部塞进笔记。选一个具体困境，取最能改变读者下一步行动的成果，反推材料和指令。

| 简历岗位雷达AI助手 | 收藏了很多JD，今晚不知道先投谁；秋招/转岗信息杂 | 简历＋目标方向/城市/届别等 → 联网找岗、核对条件、解释匹配、排序 | 岗位表：岗位/来源、城市、薪资、匹配理由、缺口、优先级；HTML重点局部 | “先把岗位排个队”；硬条件先于匹配分。分数不是录用概率，不把公司招聘首页冒充岗位详情 |

## 源图值得学的关系

6张图的文件与来源见 [资产索引](../assets/learning-20260915/manifest.json)。

- 验真：先给便于扫读的结论表，再给来源、原文与温和回复。读者要的不只是“真假”，还有怎么跟家人说。
- 票务：提示词明确出发条件；输出把出发/到达/价格放一起，突出推荐方案。用具体对比承担卖点，不让装饰充当成果。
- 搭子原界面是清楚的品牌、派活内容和结果区域。外部笔记可改变风格，内部小字、控件和表格不能任由模型重画。
- 原图也有缺陷：验真总数与类别数曾不一致；票务是历史日期。学习展示方法，不沿用错误或过期数据。

## 把一行方向变成一篇

1. 写触发时刻：“今晚要决定先投哪三份”，比“求职效率提升”具体。
2. 找决定性条件：“2027届、没有全职经验、杭州/上海”，它们必须改变筛选。
3. 选一个可见结果：“优先/待核对/暂不匹配，附理由”，而非“全面赋能”。
4. 写提示词，让它确实产出这份结果；删掉没有材料支持的要求。
5. 选合适载体：对照、表格、地图、时间线、成品画面。最后才定字体颜色。
6. 正文补充怎样理解和继续用结果；图文不要原封不动重复同一段卖点。
