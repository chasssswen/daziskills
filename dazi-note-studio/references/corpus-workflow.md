原文与 451 张未重绘原图随 Skill 保存于 `assets/corpus/`。所有图片路径相对 Skill 根目录；不需要原项目绝对路径、网络、账号或 API Key。采集日期 2026-09-02，来源与图片校验值见 manifest.json。

新笔记默认配合独立的界面物料库使用：原笔记用来提取场景和构图，`assets/ui-library/` 用来调用原始产品素材。两者作为生图的不同参考输入，详见 [物料库与场景生图](material-library-and-scene-generation.md)。

## 每次调用实际检索

运行 `python3 <skill>/scripts/corpus.py search 简历 面试 PDF`，按本次场景替换关键词；再用 `show A023` 读全篇正文、逐页 OCR 与原图路径。评分只作检索线索，不代表题材一致或功能已验证。

为一次笔记挑选约 3–5 篇有用案例，打开每篇全部原图；总览帮助理解顺序，准备使用的 UI 要另外看原尺寸。记录在本次输出的参考选用说明：案例编号、场景阻力、输入对象、功能动作、成品、叙事顺序、构图方法、借用与放弃的部分。不要仅写“参考过 96 篇”。无需每次重新精读全部 96 篇，但必须真的检索与看图。

## 按证据用途选择

- 同场景同功能：优先使用，仍不能称作本轮新实测。
- 同功能不同场景：可展示真实入口或通用步骤，内部注明原素材用途；不能把原交付物说成新任务成果。
- 同场景不同角色：只适合解释观察视角。例如 A023 是 HR 筛选简历，不是求职者优化简历；展示该例可说明岗位要求与经历如何匹配，不能只改文件名冒充求职者实测成果；可提取通用组件，重新创作符合求职者流程的完整演示内容。
- 只借构图：无需复用图中所有人物、文案或界面。换成新任务自己的对象，保留“对比、过程、结果”的表达机制。

找不到完整案例，要具体标出缺输入、执行还是最终结果。继续做可完成部分；创作简历与参考操作可以组成来源记录清楚、面向使用者的教程，但不可声称已经实测一键输出该份 PDF。若用户要求当前完整实操证据，必须取得适用操作条件或截图后才算完成。

## 把画面做成能看见的任务

样本常把 Excel、PPT、PDF、生成网页的结果大面积铺开，再用短标签解释功能；UI 承载真实输入和执行细节。避免把所有主题缩成“白底大标题 + 三条建议 + 角落小截图”。

简历可以先展示同一段经历改前改后、岗位词与经历的对照，再给输入和交付要求。结果先行不等于伪造软件输出：自制内容在内部记录为创作成果，公开文字不假称亲测；可与预采集的真实产品窗口组件合成使用演示，不称为原始实测截图。正文应解释搭子的跨文件处理如何对照旧简历与 JD，以及如何提出 PDF 交付要求。

每页解决不同问题，选择适合的主体尺寸；不用同一图框重复五次。原样引用的实测 UI 保持上下文和原文；情景演示允许在真实组件中加入新任务内容，保留正确控件和功能逻辑。图外可标注功能。官方 Logo/IP 原样合成，文字独立排版，不横向压缩。

批量时同时改变叙事顺序、主体、构图与文字密度。UGC 实拍、结果对照、MEME、排版攻略是选择空间，不是每篇都要包含的清单。
