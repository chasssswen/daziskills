# 能力 → 场景 → 成品 → 画面

以下是从样本提取的场景方向；功能名称和范围以 [产品功能与安利映射](product-features.md) 及用户最新核心功能总结为准。按下表先确定主推功能，再展开任务；场景名称不等于原生功能或 UI 入口。标题均为创作方向，不是实测声明。

| 场景方向 | 应明确安利的核心功能 | 功能落到本篇的动作 |
|---|---|---|
| 多文件对照、文档知识提取、申论材料复盘 | 跨文件处理 | 读多份文件，按依据比对/提取，再形成带来源的对照结果 |
| 表格整理、跨表月报 | 多源数据分析 | 清洗、关联、汇总原表，产出同口径图表与结论 |
| 录音结构化、会议资料 | 按实际资料和过程选择复杂任务拆解与执行或跨文件处理 | 录音读取能力不能仅从跨文件文档列表推断；缺验证可用用户提供的转写文本及其他文件演示 |
| PPT 生成、分课时教学 PPT | PPT 制作 | 资料和受众 → 结构、配文配图、排版 → 可编辑文件 |
| 旅行规划、市场信息汇总 | 深度调研 | 围绕实际问题检索、核对来源、形成报告或方案；仅整理已有行程文件时改用跨文件处理 |
| 专属网页工具、图像编辑、商品设计、兴趣图纸 | 设计与视觉产出 | 按素材、参数和需求生成或修改设计；网页运行能力另以实际交付为准 |
| 教学辅助 | 按产物选 PPT 制作、跨文件处理或设计与视觉产出中的一项 | 先确定本篇到底制作课件、比对材料还是做交互视觉；不要泛写“教学功能” |
| 定时信息整理 | 复杂任务拆解与执行；手机派活场景可辅以多端协同 | 展示实际步骤、电脑执行和文件；定时入口与连接条件另核实 |
| 直播二次分发 | 直播内容总结 | 从直播来源提取重点、高光，形成有对应依据的内容素材 |
| 同选题多平台内容 | 自媒体内容生产 | 从选题到文案、封面、素材、发布方案，保持内容对应 |
| 文件归档交接 | 文件智能管理 | 指定分类/去重规则，展示目录和清单变化 |
| 常用汇报格式 | 长期记忆 | 指出记住的格式要求，展示后续任务如何沿用 |
| 企业受控任务 | 企业安全管理 | 结合实际任务说明权限、审计、隔离或人工确认环节 |

多端协同、自然语言派活也可以独立成篇，前提是本篇的主要卡点确实是跨设备交任务或交代需求。不要每个主题都附带宣传全部辅助能力。

| 能力方向 | 场景中的阻力 | 必须进入输入的约束 | 可检查成品 | 封面/内页证明方式 | 对应样本 |
|---|---|---|---|---|---|
| 多文件对照 | 会前发现两份参会名单人数不同 | 匹配键、重名处理、忽略字段 | 仅在A/仅在B/重复项/待核对表 | 两列名单圈出一个差异；内页展示输入和差异分类 | A017 |
| 表格整理 | 月报合并时日期和客户名称格式不一 | 原表、统一规则、空值处理 | 统一表+变更明细 | 同一行前后对照，保留原值和新值 | A016/A020 |
| 录音结构化 | 面试后回听录音找项目经历 | 录音、岗位、所需栏目、原话依据 | 纪要、证据摘录、待确认点 | 办公场景+纪要局部；不以自动评分代替人员判断 | A021/B030 |
| 文档知识提取 | RFP条款分散，答复怕漏 | 招标文件、内部资料、答复边界 | 条款对照、来源位置、答复草稿 | 问题→依据→草稿的同一行链条 | A025 |

| 专属网页工具 | 生活记录分散，找不到下一步 | 字段、状态、设备、保存与备份需求 | 可运行单页、一次录入结果、导出文件 | 碎事清单→一条记录→工具界面 | B020/B024/B032 |

## 场景有效性的判断

写出“因为这个约束，所以输出里出现这个安排”。例如：

- 因为带老人且不能连续走一小时，所以路线中显示休息节点和公交替代。
- 因为名单可能重名，所以匹配键采用编号，姓名相同而编号不同进入人工核对。
- 因为月底要交接，所以记录表包含负责人、下一步和资料链接。
- 因为商品瓶型必须不变，所以生成图保留瓶身比例、瓶盖和标签，并逐项视觉核对。

约束只出现在正文情绪里、没进入输入或成品，就不足以支撑“专属”。

## 同一能力如何产生不同笔记

以“整理材料”为例，至少可分三条不同任务链：

1. 会前：两份名单找漏项 → 缺失名单 → 表格对照封面 → 核对教程。
2. 会后：录音找行动项 → 负责人/截止日/原话 → 桌面便签封面 → 过程演示。
3. 周五：五天记录整理汇报 → 进展/风险/下周安排 → 时间线封面 → 成品倒叙。

这里变化了任务对象、使用时刻、输出结构与证据类型；“行政换HR、蓝色换紫色”不构成同等程度的变化。

## 产品执行指令骨架

```text
我需要在【触发时刻】完成【具体任务】，使用者是【对象】。
已提供【材料】，请以材料为依据，不补造缺失事实。
要求【影响结果的约束】，优先解决【一个主阻力】。
请交付【格式】，包含【字段/模块】，让我能【下一步动作】。
缺失内容标出待确认；先确认会改变方案的关键条件。
如果涉及网页工具，请说明哪些功能已实现、哪些需要外部服务，并给出可验证的一次操作。
```

输出格式按真实任务选，避免所有场景强制变成 HTML 工作台。单次对照任务，一张表往往更合适。

指令给搭子执行，介绍句给读者理解。两者都需要：即使指令本身不写功能名，正文和图片仍要说明这条任务用了搭子的哪项功能。图文完整示例见 [文案与画面](copy-and-visual.md) 的考公案例。
