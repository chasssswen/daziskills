## 14 项核心功能如何进入图文

每篇选一项主推，必要时加辅助功能。下列话术是可按实际素材改写的功能介绍，不是虚构的个人使用记录。

| 核心功能 | 适合切入的任务 | 正文可明确安利的动作 | 图片应让读者看见什么 |
|---|---|---|---|
| 自然语言派活 | 不知道怎样把复杂需求交代清楚 | 用百度搭子的自然语言派活，把目标、资料、限制和交付格式一次说清 | 具体需求 → 搭子理解/确认 → 任务方案；标出一句话里的关键条件 |
| 复杂任务拆解与执行 | 一件事要连做整理、分析、制作 | 让搭子把任务拆成步骤，处理材料、执行并根据阶段结果调整 | 同一任务的输入、步骤状态、阶段文件和最终交付，说明搭子执行了哪几步 |
| 跨文件处理 | 两份名单不一致；作答和解析分散在 PDF、Word | 用搭子的跨文件处理读取多份文件，按指定依据比对和整理 | 原文件名称/格式 → 读取、比对、提取 → 带来源的差异表或报告 |
| 跨应用协同 | 浏览器查资料后还要填写和导出 | 用搭子的跨应用协同串起查询、填写、整理、导出 | 实际涉及的应用和同一数据流；关键操作与结果。外发或提交按授权执行 |
| 文件智能管理 | 文件夹混乱、重复文件难交接 | 让搭子按规则分类归档、去重或转换格式 | 同一批文件的原结构 → 规则 → 目录/清单；涉及删除保留人工确认 |
| 多源数据分析 | 多张月报口径不统一，难看出变化 | 用搭子的多源数据分析清洗、跨表关联、汇总，再生成图表和结论 | 原表片段、匹配规则、同口径结果和可追溯图表；数值必须相互一致 |
| PPT 制作 | 有季度资料，卡在汇报结构和排版 | 用搭子的 PPT 制作，把主题、资料、受众转成结构和配文配图，交付可编辑 PPT | 输入资料/结构确认 → 关键成品页 → 可编辑 PPT 文件。静态拼图不能独自证明可编辑 |
| 深度调研 | 一个问题的资料分散，来源相互冲突 | 用搭子的深度调研检索资料、交叉验证并形成结构化报告 | 研究问题、来源与日期、核对过程、报告结论；引用需能回查 |
| 设计与视觉产出 | 商品图难组成详情页；需求难变成页面方案 | 用搭子的设计与视觉产出，围绕已确认素材、卖点和风格生成设计并修改 | 原素材/明确需求 → 设计动作 → 同一商品或页面的成品和修改局部 |
| 直播内容总结 | 一场直播难拆成后续内容 | 用搭子的直播内容总结提取重点、金句，再整理成短视频文案和社媒物料 | 直播来源/片段 → 摘要和高光 → 对应内容素材；时刻与引用有依据 |
| 自媒体内容生产 | 有选题但要分别准备正文、封面、素材 | 用搭子的自媒体内容生产，把选题推进到文案、封面、素材和发布方案 | 同一选题 → 标题/正文 → 封面与素材 → 内容包；生成发布方案不等于已自动发帖 |
| 多端协同 | 人不在电脑旁，任务要用电脑里的资料 | 用搭子的多端协同，从手机派活，让电脑执行，再在手机看结果 | 手机端输入 → 电脑端执行 → 手机端成果；展示对应任务及必要连接条件 |
| 长期记忆 | 每次都要重说工作格式和偏好 | 搭子的长期记忆可记住常用格式、习惯和要求，让后续任务更贴合偏好 | 已提供的偏好 → 后续任务沿用该格式的对应字段；不夸大为永久、全量或无条件记住 |
| 企业安全管理 | 企业任务要明确权限、留记录、确认关键操作 | 搭子的企业安全管理支持权限控制、操作审计、沙箱隔离和高风险动作人工确认 | 与场景有关的权限/确认/记录环节；没真实界面用流程示意，不虚构认证或绝对安全 |

## 功能、套件与产物的关系

- 核心功能是讲价值的依据，例如“PPT 制作”“跨文件处理”。自然口语可说“用搭子同时读几份文件做对照”，但同一笔记至少一处明确点出其功能归属，图文不能只剩泛称。
- 源文档提到“设计套件”“自媒体套件”“金融套件”等场景或套件。涉及入口时核实实际版本；不要把表中每个能力名都画成一个菜单按钮。
- “申论漏点复盘表”“守宫台账”“招聘看板”是搭子在场景中处理或生成的成果。不得据此编造原生“申论批改套件”、内置专用数据库或未接通的持续服务。
- 设计套件的页面设计可归入“设计与视觉产出”；自媒体套件对应“自媒体内容生产”；金融场景按实际任务落到“深度调研”或“多源数据分析”等，不能扩展成投资收益承诺。
- 历史样本里的“自动化任务”可学习其设置、执行与结果展示。若本篇具体宣传定时执行，须核实周期设置和运行条件；不能仅凭“复杂任务拆解与执行”推断所有任务都支持后台定时。

## 从功能到卖点的写法

```text
场景：谁在什么时刻，处理什么资料？
卡点：具体卡在哪个动作？
主推功能：搭子的【功能名】。
任务交代：提供【材料】，按【标准】处理，交付【格式】。
执行动作：搭子【动作1】→【动作2】→【动作3】。
可见结果：【有内容的交付物】，圈出对应卡点的字段或变化。
安利落点：读者拿着结果能够【具体下一步】。
```

功能安利要解释使用理由。例如名单场景的价值是“把漏项与待核对项分开，照着清单逐项确认”；不能只补一句“支持跨文件处理”就结束。
