# 界面物料库与场景生图

用户要求的主工作方式：先采集一批搭子界面成为物料，再学习 96 篇怎样把界面、成果、功能和使用场景结合，用生图创作新笔记。临时跑一次任务截图，只是补充物料的一种方法。

## 两个阶段

**积累阶段**：采集常用界面和代表性任务，保留可复用组件与来源。需要登录时及时明确告诉用户在哪个页面登录；已有登录和授权继续使用。覆盖不同功能入口与状态，不以同一页面十张近似截图充数。

**制作阶段**：先检索图库和 96 篇，再确定场景、主卖点和构图；选素材 → 场景生图 → 保真合成 → 检查 → 交付。不默认要求每一篇都现场操作一遍产品；新场景的指令、过程内容和结果可作为一组情景演示创作；用户另外要求实测/专项采集时才补操作。

2026-09-17 用户再次确认：原始搭子界面素材够用，就可以用“已有真实界面＋AI编辑”直接生成新场景的使用图，不必重新截图。生成时同时提供原始UI与本篇准确文本，保留产品结构，替换场景内容；每篇展示可读提示词和打开的对应成果。新合成图不能反过来替换原始UI库作为产品原生证据。

## 图库结构与检索

便携库位于 `assets/ui-library/manifest.json`，图片为其中的相对路径。查询：

```bash
python3 scripts/ui_materials.py search 简历 PDF 输入
python3 scripts/ui_materials.py show U004
python3 scripts/ui_materials.py verify
```

已补齐的16篇审核稿/72图见 `assets/review-notes-20260915/manifest.json`，先本地查标题和序号、读正文和原图，不反复开浏览器。投稿成图中的合成界面不自动成为原生UI依据，借用控件需与真实UI库核对。

与 `scripts/corpus.py` 配合：前者查可复用产品物料，后者查原笔记的叙事与构图。不要把两者混为产品功能证明。

建议按实际采集情况分类：品牌、首页/新任务、附件与派活、技能/套件、任务执行、文件交付、成果预览。采集有代表性的界面和状态即可，不强行穷尽每个功能。主功能未启用、连接器未接通或任务未运行时，记录入口状态，不补写成功结果。

每条素材记录：ID、相对路径、来源URL、日期、分类、适用功能/场景、当前状态、可复用范围、原截图裁切坐标、尺寸与SHA256。全屏原图留在项目采集目录，供追溯；便携库优先保存不含个人账户区、无关任务和私人文件的界面裁切。

## 从原笔记提取创作方式

挑 3—5 篇，按图观察：

- 场景怎样让读者认出自己的问题：工位、通勤、桌面、考场准备、材料堆或一个具体动作。
- 界面物料在哪里：屏幕里、放大浮层、手持文件旁，或前后成品之间；为什么那个位置能说明卖点。
- 结果怎样吸引人：完整成品、一个明显变化、大幅局部或可复用资料。
- 钩子、短句和标记怎样带视线；原页面的内容密度、留白和色彩怎样配合场景。

例如 A021 是生活工作场景配原始界面嵌入；B044 以生活物件与生成氛围相接；A026 先铺开产物；A020 强调同对象变化。借方法，重新组织画面、人物、道具、文案与素材，不冒充原作者；用户允许的第一人称经历和时间反差可作为本篇角色化UGC创作，内部区分文案设定与实测。

## 生图是画面创作步骤

使用当前内置图像生成工具。给它已看过的原笔记作为**风格/构图参考**，选中的搭子界面和成果作为**内容物料参考**，另说明本次场景、情绪、观看顺序、核心卖点、精确文字和素材位置。先创作画面的整体关系，不能把生图降级成生成空底色。成果型玩法可以直接以同对象前后图或成品作为画面，不强制添加人物、道具、电脑或装饰背景。

可选：UGC桌面/使用现场、照片拼贴、反差前后、MEME、手账攻略、杂志式成果展示。同篇有识别度，页面主体随内容变化；同批不同笔记在场景、主体、构图与叙事上明显区别，不只换颜色。

生图提示词要说清：

```text
读者/触发时刻与所处环境：
这一页要表达的功能和具体收益：
参考笔记路径与借鉴的构图关系：
选用的界面/品牌/成果ID和用途：
画面主体、视觉顺序、精确上图文案：
界面在屏幕、放大层或文件中的位置：
需要保持真实的内容与可做场景化变化的部分：
```

关键 UI、Logo 和长中文存在变形风险时，让生图完成场景、人物、道具和视觉关系，保留合适位置；再等比嵌入原始 UI/成果，独立排版精确文字。尽量使用正视或易于保真的屏幕角度。也可直接生成融合画面，但必须逐字检查；发生失真就回到原图合成，不能接受“看起来像”的错误界面。

## 内容和来源准确

场景可以由AI演绎，人物不冒充用户或参考作者。真实场景感是视觉目标，不等于声称拍摄现场真实发生。在内部记录AI场景与来源；公开表达不能把合成内容冒充亲测。需要AI属性说明时简短准确，不用“原案例”等制作口吻。

原界面品牌、控件和功能逻辑保持准确。用户明确要求素材式场景演示时，可以基于真实界面外壳创作新的输入、对话、文件名和成果，演示中各处保持同一任务；新内容不再作为原始截图或实测记录。原始源素材保留不覆盖，内部清单标记为合成稿。不能把HR筛选业务逻辑仅换名字套成求职者优化，也不能创作不存在的按钮或产品能力。

每篇仍需看得到：搭子品牌、具体功能、派活提示词、对应成果效果。效果可以是当前创作的行程、简历或其他示例成果，与提示词逐项相应。内部记录创作来源；发布文字按使用者需求表达，不印“原案例、用户提供案例、效果示例”等台账文字，用户认可的UGC体验和时间反差按本篇设定创作，不把文案设定记成实际测试数据。必要属性说明准确简短。

## 交付检查

- 场景参与了卖点表达，能看出人在做什么；不是单纯换底色的说明卡。
- 确实调用了可追溯的界面物料和选定参考图；截图有内容且可读。
- 提示词要求在效果中有落点，优化有同对象的前后差异。
- 生图没有改坏品牌字形、按钮、功能名、数字或成果内容。
- 封面有明确钩子；无页码徽标和私信领取话术；文案符合本次实际素材状态。
