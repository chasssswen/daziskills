# 产品照变海报：文案、逐图提示词与搭子界面编辑

适用：烘焙上新、电商主图、小店产品宣传等“同一商品换一种展示”的图文。依据用户2026-09-17提供的原稿和三篇返修要求整理；不是所有搭子笔记的固定模板。

先看[原稿拆解](bakery-poster-learning-20260917.md)，再按需打开[三篇9图与完整提示词索引](../assets/examples/bakery-20260917/manifest.json)。索引所有资源路径以Skill根目录为基准，不依赖原电脑。每张图旁有同名 `.prompt.md`；包含实际执行的参考图顺序、完整生图指令及必要的最终局部修改。贝果的两次修正前图片单独存放，不能当最终稿调用。

## 1. 文案：说清一个小烦恼和一次具体改变

核心写法：**生活里的卡点 → 把什么交给百度搭子 → 我最在意什么 → 补了哪句话 → 晒出哪里变好了。** 可压成三段，不必每项独占一段。

| 角色和触发 | 开头钩子 | 自然带出功能 | 个人取舍 |
|---|---|---|---|
| 店主忙上新，图还没排好 | 面包都出炉了，海报还没出炉 | 把产品照和喜欢的海报一起传给百度搭子，让它借大字和商品放大的排法 | 可颂再大点，字别压在面包上 |
| 蛋糕拍成了工作台存档 | 蛋糕没换，上新图终于换了 | 借参考图的主次关系，换成粉白、留白多的版本 | 草莓别凭空多两颗，奶油别换样子 |
| 原味贝果照片像备货记录 | 背景太诚实了 | 让百度搭子排成蓝白早餐小报 | 原味就是原味，别加芝麻和夹心 |

不要只换产品名套三遍“开店的朋友是不是经常发愁”。三篇分别从时间冲突、拍摄落差、背景吐槽进入，同一能力也能写出三个视角。品牌出现在真实动作里：“传给百度搭子”“又补了一句”；不靠末尾标签完成安利。结尾可以说完整海报和指令在哪一张，不加私信领取。

成果评价要可看见：“产品更大”“粉色淡了”“保留两只贝果”。“高级、智能、效率拉满”不能替代变化。发布图不要印“原案例、原稿指令、用户提供案例、交付闭环”等幕后话；图内只放读者理解任务所需的文字。

原稿里的价格、配料承诺、27层工艺、无添加等不随风格迁移。新稿若没有商品事实依据，就写已知产品名和普通场景短句。UGC创作设定与实际测试记录分开；本批产品原料和场景均由AI创作，不记录为用户实拍或搭子实测输出。

## 2. 两种提示词分别保存

**读者发给搭子的派活指令**应像正常人说话，包含商品、参考范围、不可改项、版式/文案和输出。简单任务一小段就够：

```text
用图1的【商品】做【比例】上新海报。图2只借【主次/文字与商品的关系】，
改成【自己的视觉方向】。保留【数量/形状/摆放/配料】。
写“【标题】”“【副文】”，不加【未提供的价格或承诺】。输出PNG。
```

追加话术应解释一个可见改变，如“粉色再淡一点，别挡住草莓”。不能只展示一句“帮我做高级点”，然后成果突然拥有未交代的完整设定。三篇的原句见各目录 `搭子提示词.txt`。

**幕后图像生成指令**交给生图工具：说明参考图分别负责什么、主体占比、排版位置、精确文字、UI保真与禁改区。它不会作为用户聊天文本印到图上。不要把“图1是UI外壳、图2是成果素材”等制作说明混进搭子对话。

## 3. 每张图承担什么：先生成成果，再排笔记

制作顺序可用：确认商品原料 → 生成完整海报03 → 制作成果封面01和界面页02 → 定向修正。发布顺序仍为01、02、03。先得到准确成品，才能让封面、预览器和独立海报始终显示同一张成果。

| 发布页 | 要回答的问题 | 生图提示词必须说明 |
|---|---|---|
| 01 成果钩子 | 同一商品变成了什么？ | 原照与成品身份、布局与面积、短标题、视线方向；不要让产品偷偷换款 |
| 02 搭子使用页 | 我给什么、怎么说、拿到什么？ | 原UI依据、两附件及缩略图、可读派活指令、追加要求、输出文件名和打开后的成品 |
| 03 完整成果 | 这张海报到底长什么样？ | 已确定商品、精准文案、配色与构图；大幅完整作品，不再塞教程和功能栏 |

三页只是本次信息量的选择，不把所有后续笔记固定成三页。每篇全篇有搭子标识、UI、指令与成果即可，纯成果页无需强加工具Logo。

## 4. 批量排版：改变大小与方向，不只换颜色

用户最新要求是“有区别就好”：不强制每篇完全不同的艺术风格，不为差异添加无关人物和MEME。先给三篇画不同线框，再选字体颜色。

| 篇目 | 封面线框 | 使用页线框 | 完整范本 |
|---|---|---|---|
| 巧克力可颂 | 上方约60%大成果，下方原照和短注 | 中部横向窗口，左对话右预览 | [封面提示词](../assets/examples/bakery-20260917/croissant/01.prompt.md)、[UI提示词](../assets/examples/bakery-20260917/croissant/02.prompt.md)、[海报提示词](../assets/examples/bakery-20260917/croissant/03.prompt.md) |
| 草莓蛋糕 | 左上小原照、右下大成果，轻微相反倾斜 | 上方输入区，下方错位预览，旁边追加指令 | [封面提示词](../assets/examples/bakery-20260917/cake/01.prompt.md)、[UI提示词](../assets/examples/bakery-20260917/cake/02.prompt.md)、[海报提示词](../assets/examples/bakery-20260917/cake/03.prompt.md) |
| 原味贝果 | 上方一张大成果，下方原照/参考/UI三小图 | 左宽UI与结果，右窄个人批注 | [封面提示词](../assets/examples/bakery-20260917/bagel/01.prompt.md)、[UI提示词](../assets/examples/bakery-20260917/bagel/02.prompt.md)、[海报提示词](../assets/examples/bakery-20260917/bagel/03.prompt.md) |

轻斜的是整张照片或卡片，不拉伸字体；密集UI尽量正视。封面缩略UI只承担“用了搭子”的识别，完整指令放可读的内页。版面挤了先删装饰、缩短外部标题，不把提示词缩成糊字。左上角不放页码徽标。

## 5. 用原始搭子界面AI编辑新任务

已有物料够用就直接编辑，无需每篇重新登录或实际运行。先查看原图，区分官方品牌、原生控件结构、旧任务内容和外层笔记排版。投稿图中的合成区域不能自动升级成产品原生依据；必要时与 `assets/ui-library/manifest.json` 中真实采集页面核对。

本批参考顺序是：①用户原稿02里的搭子输入区；②原稿03里的对话和图片预览区；③本篇商品原料；④本篇已生成的完整海报；⑤用户原稿04的蛋挞海报，仅作排版参考。不是让模型把五张图都贴进画面，也不是将参考蛋挞改成当前商品。

固定原生品牌字形、按钮图标、控件层级和交互逻辑。按同一任务一起替换以下内容：

| 部位 | 应替换为 | 必须核对 |
|---|---|---|
| 任务标题 | 当前商品海报任务 | 不残留牛角任务/蛋挞成果混用 |
| 附件1 | 当前产品照＋产品照片.png | 缩略图、数量和商品与后续成果一致 |
| 附件2 | 原版排版参考＋排版参考.png | 不能误放当前任务已经生成的成品 |
| 用户对话 | 本篇派活指令＋合理追加要求 | 比例、商品保真、风格、标题都落实 |
| 输出文件卡 | 当前商品上新.png | 文件格式和预览器内容一致 |
| 打开的图片 | 已确定的完整海报 | 不止显示下载卡，不换另一张相似成品 |
| 当前任务状态 | 与所选完成阶段一致 | 已呈现最终完成页时，去掉误留的当前“正在执行”状态 |

可复用的幕后UI指令骨架：

```text
制作【比例】笔记内页。图1只取搭子输入UI，图2只取对话与图片预览结构，
不要继承原稿外面的教程标题。图3为当前商品，图4为已确定成果，图5为风格参考。
保留原生Logo、按钮、文件图标与层级；按本篇替换任务内容，不新增功能按钮。
上传两附件：图3「产品照片.png」，图5「排版参考.png」，缩略图与名称一一对应。
聊天区可读地展示：“【完整派活指令】”；追加：“【具体微调】”。
输出卡显示「【当前文件名】」，并在图片预览器打开图4，保持成品内容一致。
页面采用【横窗/错位/左宽右窄等具体安排】，UI足够大，图外只写【短句】。
不要旧任务名、错商品、虚构选择器、变形字体、页码徽标或私信领取。
```

比例可直接写进派活指令，不根据原稿一句话就编造“固定弹出尺寸选择器”。做整页UI编辑时让工具看得到真实参考，不仅在文字里说“像搭子”。对话长则减少外部装饰、拆成两页或缩短派活指令；别无依据重画密集中文。

## 6. 定向修改与最终检查

完整生成后检查“原料 → 附件 → 提示词 → 预览 → 独立成品”五处，而不只看整体漂亮。发现局部错漏，提示词用“保留哪些，只改哪里，换成哪张原图，不能影响什么”，避免重做整张导致新错误。

本次贝果返修已保存实际提示词：封面输入区附件名残留旧名，内页第二附件错误使用最终蓝白海报。修法是明确用原始橙色蛋挞参考替换缩略图，其余版面和贝果成品不动；同时清理完成画面里误留的“正在执行”。这是可复用的检查点，不是让以后每张图机械照抄同一次修复。

蛋糕原料的初始提示词写了六颗草莓，实际图为五颗；查看后以五颗作为本篇统一输入。后续不能只相信旧提示词，也不能因此更改真实商品事实。正式商品若数量不符，须修原料或向用户核实；本批为AI创作物料，内部已记录实际结果。

交付前确认：三篇不共用同一线框；主体没换款；文字正常；UI依据可追溯；提示词可读；成果真正打开；所有文件与商品名称一致；无甲方话术。保存每页最终图、完整幕后提示词、按顺序的参考路径、局部修改和SHA256。本批索引已按此保存9张最终图、3张AI商品原料、2张修正前画面和原稿4图。
