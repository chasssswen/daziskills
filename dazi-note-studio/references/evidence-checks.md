# 样本里的反例与对应校验

以下是对所给本地样本的检查，不推断作者意图，也不代表对产品能力的否定。

## 功能是否被明确安利

这组检查回应用户对旧 Skill 的修正：场景和文案好看，但读者仍需要知道用了搭子的什么功能。它检查产品表达是否成立，不能仅用品牌出现次数代替。

| 检查项 | 通过表现 | 需要修改的表现 |
|---|---|---|
| 有功能依据 | 主推功能对应用户核心功能总结，使用范围有来源 | 自创“申论批改套件”，或所有内容都用“AI 高效”代替功能 |
| 正文安利清楚 | 一句或相邻两句讲出搭子、功能、材料/动作和交付物 | 只有场景经验，最后“可以试试搭子” |
| 图片安利清楚 | 至少一页通过可读操作/对话展示搭子做的事，接同一输入与成果；不强制另做功能海报 | 整套是学习方法图，仅角落有 Logo；只有后台提示词，实际成图没有可读操作或对应成果 |
| 官方品牌可见 | 图片实际放入来源清楚的官方 Logo 或搭子 IP，清楚可识别 | 只有手打产品名、通用猫咪或 emoji，没有品牌资产 |
| 真实操作展示 | 内页以真实界面组件制作对应功能的操作、输入或交付演示，清晰可读且情景内容一致 | 只有空白首页、品牌、流程箭头；或把合成场景界面标成原始截图/亲测记录 |
| 输入与功能匹配 | 跨文件案例显示多个文件；跨应用案例显示真实涉及的应用与操作 | 单段文字改写被说成跨文件实测；只有手机电脑装饰却说实现多端执行 |
| 成果解释动作 | 能沿着原材料→搭子处理→成果局部回查 | 华丽仪表盘、四列表头或下载按钮，没有同案例的实际内容 |
| 派活提示词上图 | 实际成图可读到给搭子的指令；简单玩法允许附件＋一句要求，复杂任务补齐条件和成品要求 | 只有空白输入框、“把资料交给搭子”，或提示词只在正文、附件、后台生图指令中 |
| 成果效果上图 | 打开后的成品作为主体，展示全貌与关键细节；优化类展示同对象的改前改后/修改细节 | 只展示文件名、PDF图标、成功状态、下载按钮，或只说“最后导出PDF” |
| 提示词效果对应 | 图中指令的要求能对应到同任务成果里的可见内容 | 求职者优化简历，却展示HR筛选名单或扫描书页交付；其他工具自制结果冒充搭子输出 |
| 表达状态准确 | 能力介绍有依据；未运行内容不称亲测，来源与合成状态记内部台账 | 把本地自制示例说成搭子亲测，或因没有截图就完全删掉功能介绍 |
| 风格仍有区别 | UGC/MEME/反差引出不同任务，内页各自承接功能 | 为确保讲功能，把所有笔记又做成同一套蓝白教程卡 |
| 物料可复用 | 按功能和使用状态检索已采集图库，新场景内容用AI情景演示创作 | 用户未要求实测却每篇从零实操，或只有一组固定PPT截图 |
| 生图表达场景 | 场景、人物动作、物件与界面共同表达本次任务 | 只生成浅色背景，再把整套排成大标题和白色说明卡 |

策划稿标出“主推功能、正文对应句、图片对应页、输入和成果来源”。成图后再次检查实际文字和可读性；空缺任一项就补齐，不把待修正的问题留到用户审图才发现。

另标明品牌资产路径、真实操作页码、UI 来源与案例一致性。当前演示模式以真实界面素材/布局为基础创作操作画面，不要求新任务实测截图；界面准确、内容一致、来源记录清楚且发布表达不误导，即可按用户选定模式交付。

成稿检查再明确记录“搭子提示词页、对应成果页、可见效果细节、成果来源”。演示模式仍需创作同任务成果内容，不能以Logo、界面和指令代替成果；用户当前已明确采用示例/演示工作流，按此验收，不伪称实测。

验收按用户选择的模式：默认用预采集真实界面组件，AI创作当前任务的输入、过程与效果，内部记录合成来源，发布表达准确自然；正式演示成稿不要求本轮现场操作。只有宣称本次实测或用户要求本次实操复盘时，才检查对应的新任务运行与文件。不要把证据规则扩大成禁止场景生图。

## 证据层级

1. **看到了设计**：一张效果图、仪表盘或按钮。
2. **生成了产物**：有真实文件，能够打开和查看内容。
3. **单次操作可用**：输入真实/明确标注的测试数据，得到可复核输出。
4. **跨状态可用**：刷新、重开、导入导出、异常输入等按任务需要检查。
5. **外部与持续运行可用**：接通数据源、权限、连接器和调度，有执行记录。

宣传能力不越过当前证据支持的层级。该层级用于创作事实判断，不要求每篇笔记都做完整软件测试。

## 特殊内容的表达边界

- 股市与财报样本：学习有来源的信息整理和图表解释，不学稳定盈利、八种形态保证大涨或具体买卖保证。
- 热量与健康样本：生成计划的界面不证明适合个人，也不能直接照抄低热量指标或效果承诺。
- 儿童教育/心理样本：用具体课程、模型和记录演示，不虚构孩子成绩、自律或心理改善。
- 账号、密码、自动点餐：敏感数据和真实外部操作按任务授权处理。一个创作参考不构成运行、付款、发群消息的授权。

## 本次创作可用的状态说明

内部素材清单标明“用户确认/已操作/样本展示/待核实”。发布正文按真实情况表述，不强制印“案例/演示”台账标签，不把创作成果说成本次真实运行；必要的AI属性说明准确简短。
原图不可修改且其中已有错配时，不擅自改动截图里的证据；替换为同任务的真实截图，或清楚标注无法作为本篇证据的原因。


## 2026-09-15审核反馈补充

开始返修先读 [审核学习](review-lessons.md)。按当前用户标准逐项检查实际成图：

- 发布字眼清理：原案例、案例指令、用户提供案例、核心卖点、素材贴片、交付效果等制作口吻，不出现在面向读者的文字里。功能名本身可以自然介绍。
- UI与成果小字：优先准确贴图或保真排字；减行、放大或拆页，不能接受乱码。
- 内页新增信息：每页指出新输入、新结果或新判断；相同电脑与相同表格换标题不算新页。
- 品牌归属：正文不用看标签就能知道是百度搭子做了什么。
- 批次素材：同一旧简历、姓名、文件名、表格不能反复当成不同新任务；更换需贯穿输入到结果。
- 审核状态：提交、已修改、待审核、通过分开；通过的旧样本也不能豁免最新用户要求和真实性检查。

先修实际图片，再看整组预览；不能仅以修改提示词或补解释代替修图。
