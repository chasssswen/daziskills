# 文案与画面如何一起产生

## 文案：场景接功能，动作接成果

样本里常见的开头是身份、抱怨和意外发现。但最有迁移价值的是具体动作：找漏项、来回切工具、回听录音、抠轮廓、配颜色、算豆子、合并资料。开头直接让读者认出自己正在做的动作。

| 位置 | 应承担的工作 | 可用写法 | 容易失效的写法 |
|---|---|---|---|
| 标题 | 对象+矛盾/成品，建立明确预期 | “两份名单对不上，先把漏项找出来” | “这个AI真的太强了” |
| 开头 | 一个有材料、有阻力的瞬间 | “报名表和签到表人数差了几个，问题先卡在谁没到。” | 编造连续加班经历 |
| 产品转入 | 点明搭子的主推功能及具体用途 | “可以用百度搭子的跨文件处理，把报名表和签到表按编号比对，整理差异清单。” | 只写“把资料丢给AI”“让搭子帮忙”，没有功能与动作 |
| 方法 | 给足可复用输入，说明必要确认 | “重名按编号区分，缺失信息单独列。” | 每篇只说打开、输入、等待 |
| 结果 | 功能执行后，两三处可看到的差异/字段 | “按这个要求，结果要分成仅在报名表、仅在签到表和待核对三类。”实测稿则据真实结果写 | 罗列功能没有成果，或展示一张表却不说明搭子如何处理 |
| 收尾 | 下一步使用价值或相关提问 | “拿着差异表核对，原表也留着。” | 没证据的节省90%或永久省心 |

正文不用逐页复述。图片已展示操作步骤，正文补充输入条件、取舍和适用情境；图片是成品拼图，正文则解释如何得来。
“不逐页复述”不代表只在一端讲产品：正文与图片各自都要让读者识别搭子的主推功能。功能名可以重现，叙述各负其责。
标题长度、正文字数和话题数以发布要求为准。话题从品牌、具体任务、人群/兴趣中选相关项，避免继承原帖错城市、无关话题和过期优惠。

### 可轮换的标题方向

- 任务解法：【具体对象】卡在【动作】？先处理这一步。
- 成品展示：给【对象】做了一份【有形交付物】。只有真实做过才用“我做了”。
- 需求反差：为了【很小的兴趣需求】，做了个【具体工具】。
- 资料收藏：【场景】要准备的【可保存清单】。
- 纠错复盘：【同一任务】容易漏的【关键条件】。
- 定制方式：【特殊约束】的【任务】，需求要这样说。

每篇围绕一个承诺。不要把“低门槛、全自动、专业、免费、实时、永久保存”同时塞进标题。

## 封面的七种主体

1. **资料图主体**：路线、清单、步骤关系占主画面，品牌轻露出。A007/A040。适合收藏需求，资料要能单独使用。
2. **同对象对照**：左右或上下并置原始/处理后材料，差异位置对齐。A017/A020/B009。读者一眼识别改变了什么。
3. **成品拼图**：一张主图加少量细节，不平均缩小十几张。A026/B036。证明交付完整与风格一致。
4. **生活现场**：桌面、文件、设备或使用场景，标题顺着画面留白。A021/B044。使用真实素材，生成场景标明示意/AI。
5. **工具局部**：一个主界面+一条正在处理的记录。B020/B032。把可用功能放大，不用装饰性数据填满屏幕。
6. **兴趣/MEME**：角色或物件+其转化结果，用少量大字建立任务。B015/B034。梗不占掉教程空间，不盗用别人的个人故事。
7. **杂志式提案**：主视觉、单品/字段侧栏、充足留白与细节标题。B001/B029。适合审美或方案任务；不用强行把所有功能塞一页。

构图先由证据决定：图像变换适合对照，路线适合地图，周期记录适合时间线，工具适合状态演示，报告适合关键图表。颜色是后面的选择。

## 内页节奏

本用户现要求成稿包含官方品牌物料与真实操作展示页。下表是叙事节奏，不是允许省略 UI 的理由。分镜增加“品牌文件、原操作截图、来源状态”三项，按 [品牌与真实操作素材](brand-and-ui.md) 选择适用画面，至少一张内页清晰展示本功能操作。

参考中常见 4–7 页，但无需凑足。可依据任务选择以下节奏：

| 路径 | 页序示例 |
|---|---|
| 资料收藏 | 可用资料 → 条件说明 → 定制输入 → 输出细节 |
| 成品倒叙 | 主成品 → 最有用局部 → 输入 → 关键修改 → 完整结果 |
| 反差 | 原始阻力与结果 → 同口径细节对照 → 方法 → 复核边界 |
| 小工具 | 使用时刻 → 需求与字段 → 一次录入 → 状态变化 → 导出/备份 |
| MEME兴趣 | 兴趣物件 → 想得到的成品 → 参数/制作 → 图纸/材料 → 完成结果 |

不是每页都需要顶部品牌条、三个图标和两台手机。步骤图可以保持同篇识别度，改变素材尺度、左右关系和文字密度以形成节奏。

无论选择哪条路径，整组都要覆盖：**功能用途、输入与执行、对应成果**。可以合在一张有清楚阅读顺序的图中，也可以拆到几页；不强制所有笔记变成三张固定教程卡。封面为 UGC 或 MEME 时，后续仍应明确展示功能。结果图放前面时，随后解释搭子用什么功能处理了什么材料。

分镜工作表：

```text
页码 | 本页问题 | 功能关联 | 精确上图文字 | 输入/执行/成果素材 | 状态与来源 | 构图
```

“功能关联”是策划字段，不要求每页印出来；整组至少一页的实际图中文字必须明确出现主推功能及动作。功能文字、输入和成果需要相互解释，不能在无关表格旁边贴一个功能标签。

## 画面提示词必须含的信息

```text
这是一套【产品/任务】笔记的第【页】页。
本篇主推功能：【来自核心功能总结的名称】；本页承担【引出场景/解释功能/展示执行/展示成果】。
本页读者要看懂：【一个问题】。
主体：【具体素材和视觉优先级】。
布局：【主体位置、占比、阅读方向、留白和信息区】。
精确文字：【已定稿的标题和必要说明】。
功能页必须实际出现：【百度搭子 + 功能名称 + 本页具体动作的短句】，不能只放 Logo。
任务关系：【输入材料】→【搭子执行动作】→【对应成果】，本页显示其中哪些部分。
视觉语言：【摄影/手绘/杂志/表格/MEME等】，以及配色、字体气质、光线和材质。
证据资产：【实际文件路径】，保持哪些内容不变。
素材状态：【实际产品截图/实际结果/自制流程示意/结果示例】；示意不是产品 UI。
与同篇其他页的关系：【延续元素和本页变化】。
不要添加未经确认的价格、数据、产品名称、UI或功能。
```

UI、原始图表、精确品牌资产可以独立合成，生成模型负责背景、插画和氛围。每页中文实际渲染后检查，不能仅凭提示词正确就认定成图正确。

## 原创变化与质量

复用功能解释逻辑，重新选择真实材料、场景条件、页面叙事和构图。不照抄原句、虚构人设，也不承诺“保证通过查重”。
一批内容用以下差异表审阅：

```text
篇号 | 任务对象 | 触发时刻 | 主推功能 | 正文功能句 | 图片功能页 | 主证据 | 叙事顺序 | 封面主体 | 构图 | 密度
```

两篇若只是换岗位词或换色，优先换任务对象与证据；相同 UI 连续复用时，必须说明本篇新增的使用问题与状态，不能把相同功能页当新案例。

## 考公案例：把申论场景接到跨文件处理

本例是按用户反馈修订的策划示范，未声称已在搭子运行。功能依据是用户核心功能总结；申论例子借鉴文件对照与复盘成果的表达方式，不新增原生“申论批改”功能。

这是历史策划示范，其中的示意页不能独自满足现在的正式出图要求。再次制作时要补对应跨文件处理的真实操作界面与官方 Logo/IP；没有适用截图时保留草稿状态，不套述职 PPT 的界面冒充申论实操。

**主推功能**：跨文件处理。辅助使用方式：自然语言派活。
**场景卡点**：下班做完一题，题目材料与解析是 PDF，自己的答案在 Word，反复切换却找不清漏了哪层意思。
**输入**：`题目与材料.pdf`、`我的作答.docx`、`参考解析.pdf`；三份文件对应同一题。没有文件时先准备演示材料，不把单段粘贴文本写成跨文件实测。
**执行**：读取三份文件 → 依据题目要求逐点比对 → 保留材料出处 → 整理漏点与改写方向。
**交付要求**：一份 Word 复盘文档，内含“材料依据、我的表述、遗漏或偏差、修改提示”对照表。实际执行后按实际得到的文件展示。
**使用价值**：照表回到原材料核对，再改自己的答案。

### 标题与正文示范

标题：申论一看解析就懂，自己写却总漏点？

做完题再复盘，最费劲的一步是来回翻：材料在 PDF，答案在 Word，参考解析又是一份文件。看完觉得懂了，还是说不清自己到底漏在哪。

这里可以用上**百度搭子的跨文件处理**：把同一题的材料、自己的作答和参考解析一起提供，让它逐份读取，按题目要求比对要点，再整理成一份 Word 漏点复盘文档。

需求可以这样交代：“请对照这三份文件，整理材料依据、我的表述、遗漏或偏差、修改提示四列，保留材料出处；缺少依据的地方标为待核对，不要替我编造评分。”

这样交任务，目的是拿到能回查原文的对照结果。复盘时先核对它标出的漏点，再自己改一遍答案，就知道下一步该看哪段材料、补哪层意思。

话题示例：#百度搭子 #申论复盘 #在职备考 #考公学习方法

### 五页分镜示范

| 页 | 精确上图文字示例 | 素材与构图 | 功能如何进入本页 |
|---|---|---|---|
| 1 现场 | “解析看懂了 / 自己写还是漏点？”；小字“百度搭子 · 申论复盘思路” | 下班备考桌面与文档局部拼贴，大字表现反复切文件；生成生活图标明示意 | 场景先引出问题，避免假称本人已使用 |
| 2 揭示功能 | “用百度搭子的跨文件处理 / 把 PDF 和 Word 对照起来” | 三份有名称和格式的文件 → 中部“搭子：读取·比对·整理” → 右下复盘文档，标“流程示意” | 明确写出产品、核心功能及处理动作 |
| 3 交代任务 | “这次交给搭子的活：逐点对照，保留出处” | 上方同三份输入，下方精简派活指令；红线标题目要求、原文依据、待核对 | 自然语言派活解释跨文件处理的标准；没有真实 UI 时不画对话产品截图 |
| 4 看结果 | “跨文件比对后 / 重点看这张漏点表” | 放大两三行有真实内容的四列表格，角标“结果示例”；原材料与表格出处对应 | 用同一案例证明功能的结果形态；自制示例不写“搭子已生成” |
| 5 用起来 | “沿着漏点表，回材料再改一遍” | 取同一漏点，把材料原句、原作答与改写方向连起来；尾注“依据原文复核” | 交付物进入备考动作，收束功能价值；不编造分数、通过率或提分成绩 |

示范给出的是结构和表达。制作时应有可读的真实/自制题目片段和对应结果，不能把四个空栏目画出来就算成果。若只需三页，可合并功能和任务页、合并成果和使用页；若换成 MEME 封面，仍保留清晰的功能与成果承接。
