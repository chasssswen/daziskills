# 真人口吻与画面：让人想晒的结果带出搭子

依据：原96篇库＋2026-09-15补齐的16篇/72图。原稿和逐图判断见 [逐篇学习](review-corpus-20260915.md)，退回原话见 [审核记录](review-lessons.md)。这些是表达方法，不是要求新稿照抄作者经历、图片或句子。

## 先站在分享者的位置

写之前用两三句回答：这个人刚遇到什么？为什么偏要这样做？结果哪一点让他愿意发出来？选一个主情绪：想晒、好笑、松口气、不服气、纠结或终于想明白。情绪跟着对象变化，不固定“姐妹们救命＋封神”。

真人感来自具体细节和判断：猫的臭脸、舍不得删的旅行照片、周一要交的报告、收藏了很多JD却不知道今晚先投谁。不要从“随着AI发展”“适用于职场人士”“核心能力包含”起笔。可以说不满意什么、追改了哪一句、为什么挑这一版；不要每个功能都无条件夸一遍。

用户认可第一人称UGC与时间反差创作，可按角色使用“20分钟”“用了一个月”“同事推荐”等，不一律改成科普口吻。内部记录角色与时间线，不把文案设定记成本次实测或普遍性能承诺。人物、素材、指令和成果必须自洽。

## 先选表达方式，再决定页数

| 方式 | 适合的内容 | 阅读顺序与文字密度 | 本地参照 |
|---|---|---|---|
| 晒自己的成品 | 宠物、照片、壁纸、视觉玩法 | 成品/同对象对照占前几页，最后一页短提示词或对话；正文三小段即可 | 09、13 |
| 好看得想保存 | 旅行照片、手账、可收藏资料 | 无标题或少字结果封面，多张作品，再接操作入口和一句要求 | 08、12 |
| 一个具体麻烦被解决 | 报告、PPT、周报 | 工作现场一句话→拿到的内容→关键派活/修改→自己的使用判断 | 01、06、07，注意舍弃旧泛化海报 |
| 一眼能懂的反差 | 白底商品图、简历改写、岗位筛选 | 同对象前后/错误直觉与正确判断→成果细节→怎么做 | 05、16 |
| 我替自己做了个选择 | 行程、岗位、转岗准备 | 先晒安排或清单→为什么保留这项/划掉那项→所给条件 | 10、15、16 |

这是可选表达，不是新固定模板。同批要换阅读方式、主体、媒介与文字密度；颜色最后选。成果页与教程页可以不同密度，沿用同一对象、色调或标记就能连起来，不必每页同一个外框。

## 封面钩子可以不写出来

09、13用宠物大头小身子本身吸引，08、12直接展示照片与印章成品，没有大标题也成立。想晒的东西足够好看/好笑时，让它占大部分画面，别加一套“功能、亮点、适用人群”挡住它。

办公/求职可以用具体痛点标题，但成品要兑现：喊“岗位排个队”，就让读者看到排序或先排除谁的理由；喊“PPT终于做完”，就打开可见的幻灯片；喊“简历改好了”，就有同段改前改后或成稿，不能只有文件图标。主成品与标题只设一个视觉重心，避免上半页空、下半页挤满小字。

## 功能安利嵌在动作中

正文至少自然出现一次“百度搭子＋我交给它什么/让它做什么＋拿来干什么”。Logo和话题不能替代这句话。

- 图片玩法：“我把原图和想要的效果一起发给百度搭子，让它保留花色，只改头身比例。”
- 旅行：“我把到站时间和不租车这两点先告诉百度搭子，想让它把接驳也排进去。”
- 求职：“把简历给百度搭子，让它找岗位时先看届别；分再高，不能投的我也先划掉。”
- 报告：“我让百度搭子把每段结论的出处放旁边，改稿时不用再翻那十几个网页。”

按实际场景改写，不照抄以上句子。讲一个有用的动作比堆“自然语言派活、联网调研、HTML交付”更像分享；官方功能名在有助找到入口时保留。

## 人话替换：从这批旧稿学会删什么

| 旧的制作/宣传口吻 | 更像使用者的说法（按本篇事实改） |
|---|---|
| 本案例展示简历岗位雷达AI助手工作流 | 收藏了一堆岗位，我先让搭子帮我看看哪些能投 |
| 原案例整理出12个目标岗位 | 我先看这几行，决定今晚从哪里开始投 |
| 上方为原案例指令，补充条件按本人情况填写 | 我又加了一句：只看符合我届别的 |
| 能力差距与补齐建议 | Excel我会，SQL这块还真得补 |
| 交付HTML报告，辅助用户决策 | 清单打开后，地点和要求终于不用来回切着看了 |
| 基于预采集真实界面素材的情景演示 | 删除制作台账页脚；必要的AI属性说明另按实际要求简短处理 |
| 自然语言派活实现高效内容生产 | 我就把原图扔进去，说了句“头再大一点” |
| 查看效果成品、核对结构与数据 | 我先翻了这两页，数字对不对一眼就能查 |

不是把全部词换成“我”就合格。还要有个人偏好、具体对象、动作和结果；少用“高级感、氛围感、效率提升”反复填空。可保留真实产品UI中的“查看示例”等按钮名，禁止的是图外制作方叙述，不是修改真实控件。

## 提示词要像人在用，长度由任务决定

简单玩法：两张上传附件已经说明原图和参考图，一句“把图1做成图2那种大头小身子，花色和表情别变”足够。图13第五页就是附件＋一句话＋追加微调；不要把它扩成专业提示词工程课。

复杂任务：简历/路线/报告确需材料、动作、约束、成品要求。图上放可读的关键段，正文附可复制完整版，别微缩几十行。使用者会说“做成我能打开的表”“再补雨天去哪儿”，不一定说“交付闭环”。

| 要求 | 图中对应的结果 |
|---|---|
| 保留猫的样子，只改比例 | 同一花色、表情、背景与新比例 |
| 保留照片主体做印章 | 同一建筑/宠物轮廓与对应印章，不是随便画个同类物 |
| 不自驾、次日晚走 | 接驳顺序和返程预留时间 |
| 按JD改简历、不编经历 | 同段经历修改及对应岗位要求 |
| 先查届别与经验 | 符合/待确认/不匹配和具体理由 |
| 生成PPT或PDF | 打开的内容页，不能只有下载卡 |

图内提示词、图外补充句和结果不矛盾。文件名要跟对象走；参考材料里保留的旧文件名不是产品固定字段。

## 画面去掉广告模板感

- 先选主材：自己的照片、同对象对照、打开的成品、带批注的几行、日常工作现场。电脑和人物只在帮助讲清使用情境时出现。
- 照片可保留普通地板、猫窝、手持饮料、随拍角度等生活线索。不要为了“高级”全部换成影棚、豪宅和发光悬浮屏。
- 成果型封面可以无字；UI放后面并保留官方Logo/可识别头部。品牌要求按整篇检查，不要求每页盖章。
- 实用内容可用纸张、红笔、手绘线路；MEME要把梗落到问题和结果，而不是只加像素人物。
- UI和长中文保真，放大有用部分；不能用小到看不清的表格装饰海报。允许克制的圈线，不要每句话一张卡。
- 同一张电脑换三次外框不算三页；同一成果全貌＋必要局部可以复用，但每页必须新增一个观察点。
- 简单成品晒图无需画面内页面编号；行程DAY和实际步骤标签可保留。

## 最后按真人读一遍

1. 开头是这个人想做的事，还是产品发布会？
2. 遮住装饰，是否还有想晒/想保存的结果？
3. 至少能说出一个具体变化或取舍，而不是只说“好用”？
4. 正文能读出百度搭子做了什么；整篇看得到品牌、准确UI、提示词、对应成果？
5. 教程是否为当前对象重写，附件、指令、结果对得上？
6. 删掉重复夸赞、甲方页脚和无用总结后，还能否更短？

不凑统一篇幅，不要求每篇一定有吐槽、教程或结尾号召。图文互补，功能看得懂，分享欲成立，就可以结束。
