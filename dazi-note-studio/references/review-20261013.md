# 2026-10-13审核反馈与生产门槛

## 最新追加：产品通知必须同步到交付

用户明确反馈：百度搭子没有skill商店；当前不使用英文名；图文要有提示词或步骤，不能让读者以为点进产品就有展示功能；玄学从个人搭建工作台角度做。此条优先于本文件下方旧素材解释。

1. 禁止引导去skill商店、技能商店、技能市场、插件商店找/选/安装技能。图片也检查历史侧栏、输入框“快速调用技能/套件/插件”占位提示、加载日志及无关首页推荐；采用可用输入局部，裁去过时区域，不杜撰替代控件。
2. 新交付统一“百度搭子/搭子”。检查正文、话题、海报、Logo、UI角落和成果正文内的英文品牌；PPT、HTML、CSV等格式名不属于禁用品牌。旧原图只做历史来源。
3. 每篇展示可读提示词或完整步骤，并把可复制需求写进交付笔记正文。工具成果说明个人生成关系：“我的材料/要求 → 输入提示词 → 生成文件/工作台 → 保存打开、使用与修改”。只有漂亮结果、空白首页、Logo或一句“一键生成”不能通过。
4. 星盘等玄学选题讲个人资料工作台：自己的材料、术语、来源、阅读笔记、追问清单，展示如何搭建。生成成果内部也不能有确定性性格、人生、财运、健康或感情判断，不能只在图外加一句“不预测”掩盖矛盾。
5. 收到新通知立即复核在制与交付中的全部版本，建立页级修改清单。修文案、修图片后重看实际最终图，重建预览和ZIP。仅改skill、只搜正文、只改提示词或仍给旧ZIP都不算落实。

本轮追加复核对象为6主题12篇54图。发现旧技能/套件调用提示、无关首页入口、成果归属不够清楚、星盘内部解读及手抄报参数引导问题，执行局部返修；未发现新交付文案和图中英文品牌残留。页级证据、实际修图提示词和最终包校验保留在对应任务的内部制作记录，以最后核验记录为准，不把制作完成写成外部审核通过。

适用于百度搭子图文改写及返修。用户当轮纠正高于旧的原图微调方案；不是要求所有未来创作都采用一个固定版式。

## 制作流程中的落点

1. 开工前写一句“百度搭子根据什么输入，制作了什么成果”，再列原稿可保留的功能与需要纠正的误导。原文与审核冲突时落实最新反馈，不机械保留错误宣传。
2. 每页先识别原图表达语法，再记录真实UI保护区域和选定的1—2个修改方向。人物、软件/案例、背景或上下/左右布局可择一组合。A/B有实质差异，且保留原来的朴素网感；不把所有图重新包装成精致AI海报。
3. 工具型选题必须串起“可复制提示词→百度搭子处理→打开后的工作台/文件→使用方法”。工具名称只是生成成果的名字，不能包装成另一个现成App来推荐。
4. 真正替换图片和发布文案。截图局部可保真，原产品控件与品牌结构不乱造；提示词、结果、文件名和正文条件一致。用AI合成的演示在制作记录中标明，不能记成新实测。
5. 查品牌英文残留，并逐图目检。英文品牌禁用不等于禁止HTML、PPT、CSV这些必要格式词；不得把历史原文档修改成仿佛原作者当时就用中文品牌。
6. 原图、A、B并排检查：所选人物、背景或布局变量是否形成明显不同的新画面；只有微小位移、边框、难以察觉的色差或直接复制整页则退回。背景可单独作为改写方向，不能把“全元素重造”重新设为门槛。仍有乱码时修图，不用源图整页覆盖掩盖问题。
7. 最终逐项记录“反馈→已修改的页和文案→核验依据”。内部完成仅写已修改/待审核，不冒称审核通过。保留旧稿供溯源，新交付入口指向返修版。

## 三个重点反例

- 记账封面只写“自由记好用”，正文结尾补一个百度搭子话题：仍然没有品牌与制作动作的关系。
- 星盘图写“找百度搭子看运势”“一点不比专业的差”，正文说用AI：仍然误导为玄学专用软件。
- 人物照片、字体、配色和内页完全不变，图标挪20像素：仍然是复刻，不是图片改写。


## 同轮第二次纠正：AI味变重

用户原话：“把ppt软件改成excel（或者其他办公软件）”“把唐僧改成其他人物，比如网红表情包”“把背景改了”“把上下构图改成左右构图”“但是笔记宣言的卖点功能突出点是一样的，搭子可以干这个”“你新出的图我看了，ai味就变重了”。


必须保留原图的传播表达，而非只保留抽象主题。普通表情包保持大字、抠图和简单背景；操作页保持大幅真实界面、少量说明。禁止默认添加精致虚拟人、3D动物、布景桌面、满屏贴纸和装饰文案。选择有限编辑方向，用最少元素把相同卖点讲清楚。先检查代表页再批量，已否定风格不得混入交付。
