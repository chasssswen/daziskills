# 搭子图文场景工作室

让读者先想要图里的结果，再看懂：**给百度搭子什么材料、让它做什么、得到什么、自己怎么照着用。** 做图文就交付实际成图与发布文案，不停在策划。

## 最高创作优先级：真人网感

像一个有具体生活、偏好和小烦恼的人在分享。先确定“我为什么想做这个、最喜欢哪处变化、拿它干什么”，再把搭子放进实际动作里。功能安利可以只是“我把猫和参考图一起丢给百度搭子，让它把头放大，连原来那张臭脸都留着”。不为交代功能另加一整页卖点口号。

封面必须有强钩子，但钩子可以是好笑的成品、同一照片前后反差、值得保存的路线，不强制巨大标题。成果型笔记允许前几页纯晒图，后面一页交代提示词和操作；全篇品牌与真实UI明确可见即可，不要求每张图盖Logo、放电脑和三条卖点。正文可以短到三段，不凑字数或强塞长教程。

优先读 [真人口吻与画面](references/copy-and-visual.md) 和 [16篇逐图学习](references/review-corpus-20260915.md)。避免把“网感”简化成热词、感叹号、MEME贴纸或豪华3D背景。审核通过的旧稿仍需按用户最新要求去掉甲方口吻、重复贴片和无效装饰。

## 本用户确认的工作方式

**预采集真实界面 → 查阅96篇原图及适用审核稿 → 确定场景和具体成果 → 用AI组织使用画面 → 准确嵌入UI、提示词和成果 → 逐页检查。**

预采集与每篇生产分开。默认复用真实品牌、控件和布局，按场景创作相互对应的输入、对话与结果；不每篇从头登录搭子跑任务。用户明确要求“自己上传试试、真实跑一遍、补新截图”时才实操，已有授权继续有效。原图不覆盖；用户指定不动的截图区域保持原样。

真实使用感来自具体材料、合理操作和可见结果。内部记录原始截图、AI场景合成、重排成果及实测文件；合成图不称为原始截图或本次亲测。发布文字用自然的用户表达，不把“原案例、上方为原案例指令、用户提供案例、交付效果示例”等制作说明印在图上；用户已明确允许“20分钟”“用了一个月”等时间反差和第一人称UGC创作，可按本篇角色与时间线使用，不一律删掉。创作文案与真实测试记录分开，不能把文案设定记成实测数据。必要的来源、AI属性说明准确简短，不能靠删掉说明把合成内容冒充实测。

## 先按用途读资料

- **产品能力依据**：[产品功能](references/product-features.md) 和 [核心功能总结](references/百度搭子核心功能总结.md)。用户新资料优先；旧帖子、测试集和静态截图不自动证明当前能力已启用。
- **选题与任务设计**：[工作流方向](references/workflow-directions.md)：人群、触发场景、输入、动作、成果、上图位置。特别区分“简历岗位雷达”与“简历对照JD优化”。
- **审核与历史复盘**：[审核学习](references/review-lessons.md)。首次使用本版、批量制作和返修时读；区分提交、需修改、待审核、通过，以及本地新版本。
- **构图与界面原料**：[96篇原图库](references/corpus-workflow.md)、[品牌与UI](references/brand-and-ui.md)、[物料库](references/material-library-and-scene-generation.md)。不是只读总结，必须实际查看选中原图。

## 制作流程

### 1. 把选题缩成一个任务

写清一个读者、一个触发时刻、一个主要阻力和一个想拿到的成品。条件要改变成果：不自驾决定接驳，目标JD决定简历改写，投递条件决定岗位排序。先写一条人话功能句：

> 把简历和想找的岗位告诉百度搭子，让它联网找岗，再把地点、匹配理由和投递顺序放进同一份报告。

选择一个主功能，必要时加协同功能。别把“AI很强”“全能”“一键”当卖点本身。缺少非关键条件可记录合理假设继续；关键事实或访问条件缺失才问。动态岗位、价格、时刻、链接按实际用途核实。

### 2. 真正选参考与新素材

运行 `scripts/corpus.py search <场景/功能>`，再 `show <ID>`；挑约3—5篇，读正文、看全部图片，拟用UI看原尺寸。记录钩子、人物问题、输入、功能动作、结果、构图及借用/放弃之处，不笼统声称“已学完96篇”。无需每次重读全部。

用 `scripts/ui_materials.py search <功能/状态>` 找输入、执行、预览组件；新学习素材见 [学习资产索引](assets/learning-20260915/manifest.json)。优先本篇任务匹配的素材，不能长期反复贴同一份小A简历、PPT或电脑页面。

本地审核稿已归档为 [16篇/72图索引](assets/review-notes-20260915/manifest.json)，带正文、逐页原图、审核阶段及原批注；按序号和标题检索，直接读本地文件，已有素材不重复开浏览器。它与原96篇库分开保存。原稿中的合成界面只作参考，不能自动当作产品原生UI凭据。

用户说“2+2交叉混合”时，实际选两篇借场景/叙事、另外两篇借构图/成果展示，记录四篇ID与各自作用。组合方法，重写任务与画面；不是拼四张原图，也不照搬教程、经历和数据。

### 3. 先准备能上图的成果

按 [制作工作单](references/production-worksheet.md) 固定输入、完整派活提示词、关键成果内容和文件名。每个重要要求都能在成品找到落点。

- 岗位雷达：岗位、来源链接、地点/薪资、匹配理由、缺口和优先级；重点展示能做决定的几行。
- 简历优化：同一段经历改前改后、对应JD要求、最终简历页面；不编经历和指标。
- PPT：打开的多页幻灯片及重点页，不以PPT下载卡代替成品。
- PDF/报告：正文、表格、结论或来源等可读局部，不只放封面或文件名。
- 旅行：路线、顺序、接驳和随身查阅内容，不能只放风景。
- 图像玩法：同一个对象的原图与新图，教程指令与效果对应。

成果先行指先决定读者能看见的内容，不意味着虚构一次实测。创作成果与真实输出在内部台账分清；引用真实结果不擅改数据和结论。

### 4. 写文案与分镜

读 [文案与画面](references/copy-and-visual.md)。封面用具体痛点、反差、欲望或可收藏成品形成强钩子；后面有实际结果兑现。正文自然提到**百度搭子＋具体动作＋成果用途**，Logo和话题不代替功能说明。

图中必须有可读的派活提示词。简单图片玩法可用“两张附件＋一句具体要求”，不硬凑四段；复杂任务再补材料、动作、关键条件和所需成品。长指令可拆重点，正文附完整可复制版。不要印幕后生图指令。

每页推动一个新问题：想要什么、怎么交代、得到什么、怎么判断/使用。页数随信息决定，不固定三/四/五张。内页不能重复同一张电脑/同一表格，只换标题。

同批各篇要明显区别：改变叙事顺序、封面主体、构图与媒介；再选配色字体。可用UGC桌面、红黑纸张杂志、MEME游戏、手绘地图、成果对照等；遮住标题和颜色后仍相似就重排。

### 5. 生图、准确贴图、核验

用可用图像生成工具完成场景、人物/道具、材质和观看顺序。参考图负责构图，真实UI负责产品结构，当前成果负责内容，明确各自用途。不要让模型自由重画长中文、品牌或密集报告。

需要精确贴图时，按当前图像工具规则保留截图或等比嵌入准确组件；用户要求程序合成时可确定性排字。标题不拉伸，优先改换行与文字长度。图像编辑默认使用图像生成工具，不能擅自以Python重绘替代。保真策略见 [物料库](references/material-library-and-scene-generation.md)。

逐张看原尺寸，再看手机预览，按 [核验表](references/evidence-checks.md) 修复实际成图：

- 封面钩子有兑现，成果内容够大，提示词可读。
- 官方搭子Logo/物料和适用真实UI清楚出现，品牌、功能、状态正确。
- 人物、文件、数字、岗位、天数、条件与成果同一任务，没有旧内容残留。
- 图文没有私信领取话术、甲方制作口吻或错误产品事实；UGC角色、体验时间与结果自洽，创作设定不当作普遍性能保证。
- 左上角没有图片序号徽标；行程DAY、任务步骤等内容标签可以有。
- 本篇内页有新信息；同批有明显构图差异；没有乱码、拉伸、遮挡或糊小字。
- 真人网感：有个人动机、具体对象和对结果的取舍；图片先吸引人看成果，正文顺着动作提搭子。删掉装饰与空泛夸赞后仍有值得分享的东西，不能只剩宣传话术。

默认交付3:4竖图、有序图片、标题/正文/话题、可复制提示词、整组预览与ZIP。来源和制作记录单独保存。用户只要求更新skill时不另生成笔记；不自动发布、外传私有素材或同步公开仓库。

## 维护

新增可复用材料先记录来源、时间、适用范围和版本，再更新索引。使用 `corpus.py verify`、`ui_materials.py verify` 核验原库；禁止用AI图替代缺失原图。新学习资料及读取范围写入 [审核学习](references/review-lessons.md)，不能把收到链接、下载文件或看缩略图等同于读完原稿。
