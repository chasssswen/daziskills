# 搭子图文场景工作室

## 日常制作方式

直接看原稿、选素材、改写、做图、检查成品并交付。默认不填制作工作单，不另建素材登记、来源台账、逐页修改清单、提示词档案、审核报告或哈希清单；引用资料中的旧留档要求也按此执行。用户明确要求复盘、可复现流程或正式审核时，再补所需的那一部分。

真实界面、官号口吻、品牌和操作词准确、提示词与成品对应、改写有明显差异等成品要求保留。普通任务看最终文字和图片即可；OCR用于小字难辨或批量检查，哈希用于确有版本混淆时，不设为每次交付的固定门槛。已有资料直接复用，不重复建档。

让读者先想要图里的结果，再看懂：**给百度搭子什么材料、让它做什么、得到什么、自己怎么照着用。** 做图文就交付实际成图与发布文案，不停在策划。

## 最新制作约束 2026-10-15

本项目制作、洗稿、返修前，必读并执行[真实界面与官号投放约束](references/review-20261015.md)：封面与发布标题不能同时出现“百度搭子”；所有图文禁用英文品牌；使用真实操作搭子的界面，只允许保真截图拼版；官号投放不用素人种草感；每篇有真实输入到成品的使用指引；操作引导词逐项核对真实界面。该节是本项目现行规则，下方及引用资料中与之冲突的AI场景、改写截图和UGC旧做法不再适用。品牌仍须在正文及适用内页讲清，搭子实际生成的成果与另行AI合成的演示画面须分清。

## 最新审核门槛 2026-10-13

返修、改写和批量生产先读[本轮审核规范](references/review-20261013.md)。以下任一项不通过就返修实际成品，用户后续产品通知优先于历史参考图：

- **没有skill商店。** 不写“skill商店、技能商店、技能市场、插件商店”，不指导找、选、安装某个技能才能得到图中成果。历史截图中的旧“技能/套件调用”侧栏、首页推荐入口、输入框占位提示和加载日志也要检查；与当前任务或最新通知冲突的区域不能继续上图。优先换适用界面或裁去过时区域，不凭空补造新按钮。
- **每篇都要讲明输入到成果。** 图中至少有一段可读、可照做的提示词，或完整步骤引导；最终笔记正文内也提供可复制要求。写清“准备/上传什么 → 在对话框输入什么 → 生成什么 → 如何打开、使用或继续修改”。成果页属于个人生成的HTML、PPT、图片或脚本，不能只写“打开搭子就有”“找到某工作台”“点某功能”，让读者误以为产品原生自带这个成品。

- 新写标题、正文、话题和设计文字统一写“百度搭子”或上下文清楚的“搭子”，不再使用品牌英文名；品牌物料优先中文版本。原始归档不篡改，真实UI含历史英文标识时选用适用中文UI或保留有用局部，不能伪改原生控件。
- 文案与图片都说明“百度搭子＋输入/提示词＋制作动作＋具体成果”。记账、取名、星盘工作台等不能写成无关App推荐，或说成搭子的固定内置专用软件。
- 星盘及类似玄学主题从**我为自己搭建工作台**切入：自己的材料和需求、可复制提示词、生成HTML、保存打开与继续补充。封面、步骤、成果内部文字和正文都保持这一角度；成果里的人生、健康、财运、职业和感情判断也要检查，不能外面写学习、里面仍在算命。保留术语、资料出处、阅读笔记和待核对问题，不让人误认为百度搭子是玄学软件，不写改运、专业预测或确定性人生判断。
- 图片改写允许保留叙事和构图骨架，真实操作界面可作为局部复用；按原图的表达语法选择人物、软件/案例、背景、上下/左右布局等1—2个方向明显改写，不要求全元素重造。整页照搬、仅微移、或把朴素表情包变成精致AI广告都不合格。

产品通知收到后检查受影响的当批版本，修正文案和实际图片，更新预览与ZIP。检查封面、UI角落、输入框、成果和话题的英文品牌残留；包内使用检查过的最终版即可，不另建页级清单、哈希表或修订报告。

## 同轮追加：改变量，不升级成AI海报

用户以唐僧PPT表情包示范：可换Excel等办公软件、换网红表情包人物、换背景、上下变左右，但保留“搭子能帮你完成”的功能卖点。可以从这些方向择一或组合，不把参考全盘推倒。软件或案例一旦更换，输入、成果、UI与文案也要成套对应。

原图是简单大字、抠图表情和纯底色，就延续这种传播方式。不要自动加真人摄影场景、3D角色、装饰便签、景深和手账材质。内页优先清晰截图＋短解释；复杂画面只有原任务确实需要才采用。首轮检查封面和含真实UI的内页各一张，再批量；错误方向生成稿立即移出成稿目录，记为弃用。

## 历史创作参考：真人网感（官号投放不采用素人叙事）

本节的个人经历、第一人称安利仅供其他适用用途参考；官号投放按2026-10-15规则写产品演示与使用指引，保留清楚、直接的表达。

像一个有具体生活、偏好和小烦恼的人在分享。先确定“我为什么想做这个、最喜欢哪处变化、拿它干什么”，再把搭子放进实际动作里。功能安利可以只是“我把猫和参考图一起丢给百度搭子，让它把头放大，连原来那张臭脸都留着”。不为交代功能另加一整页卖点口号。

封面必须有强钩子，但钩子可以是好笑的成品、同一照片前后反差、值得保存的路线，不强制巨大标题。成果型笔记允许前几页纯晒图，后面一页交代提示词和操作；全篇品牌与真实UI明确可见即可，不要求每张图盖Logo、放电脑和三条卖点。正文可以短到三段，不凑字数或强塞长教程。

优先读 [真人口吻与画面](references/copy-and-visual.md) 和 [16篇逐图学习](references/review-corpus-20260915.md)。避免把“网感”简化成热词、感叹号、MEME贴纸或豪华3D背景。审核通过的旧稿仍需按用户最新要求去掉甲方口吻、重复贴片和无效装饰。

## 本用户确认的工作方式

**查阅原图及适用审核稿 → 确定任务与成果 → 匹配或补采真实搭子操作及成品截图 → 保真拼版与标注 → 逐页检查。**

预采集与每篇生产分开。可以直接复用待改写原稿或已有素材库中同任务的真实输入、对话和结果，不要求每篇重复运行。原稿缺图、不清晰、过时，或更换任务与条件后素材不匹配时，可在浏览器中实际操作搭子并截取对应界面；在用户任务授权范围内补采，不需仅为截图来源重复确认。需要本人登录或验证时再请用户处理。不修改截图内容冒充操作，不整页照搬原海报。原图不覆盖；用户指定不动的截图区域保持原样。

**真实界面指实际操作搭子的截图，不能只借用控件布局再由AI生成新界面。** 可以裁切、放大、拼接真实截图并添加外围说明，也可由AI辅助保真拼版；不得补造按钮、输入、对话或结果。每篇展示真实提示词输入与对应打开后的成果，检查文字可读、操作连贯，不要求另写来源对应表。

直接使用已有真实截图与对应成果；拼图不称为一次新实测，不另建过程台账。发布文字不印“原案例、用户提供案例、交付效果示例”等制作说明。官号投放讲场景、操作与成果，不虚构素人经历或使用时长。其他用途的创作设定也不能记成实测数据。

## 制作流程

用户指定原笔记要求“洗稿、同样核心换表达、做多个改写版本”时，先固定核心内容与关键锚点；当前环境已安装 `$note-rewrite` 时同时读取其入口，再执行下方要求。各篇表现不同，但核心内容完全相同：文字重新组织，图片参考原图，可修改主体、背景、配色、构图、排版和信息层级。核心功能、条件、过程和成果保持完整一致；不默认每篇必须更换人物、痛点、地点或作息。

### 1. 把选题缩成一个任务

写清一个读者、一个触发时刻、一个主要阻力和一个想拿到的成品。条件要改变成果：不自驾决定接驳，目标JD决定简历改写，投递条件决定岗位排序。先写一条人话功能句：

> 把简历和想找的岗位告诉百度搭子，让它联网找岗，再把地点、匹配理由和投递顺序放进同一份报告。

选择一个主功能，必要时加协同功能。别把“AI很强”“全能”“一键”当卖点本身。缺少非关键条件可合理假设并继续；关键事实或访问条件缺失才问。动态岗位、价格、时刻、链接按实际用途核实。

### 2. 真正选参考与新素材

运行 `scripts/corpus.py search <场景/功能>`，再 `show <ID>`；按本次任务选够用的参考，读正文、看配图，拟用UI看原尺寸；用户已给明确参考时直接使用，不额外凑数量或写拆解表。不笼统声称读完未读资料。

用 `scripts/ui_materials.py search <功能/状态>` 找输入、执行、预览组件；新学习素材见 [学习资产索引](assets/learning-20260915/manifest.json)。优先本篇任务匹配的素材，不能长期反复贴同一份小A简历、PPT或电脑页面。

本地审核稿已归档为 [16篇/72图索引](assets/review-notes-20260915/manifest.json)，带正文、逐页原图、审核阶段及原批注；按序号和标题检索，直接读本地文件，已有素材不重复开浏览器。它与原96篇库分开保存。原稿中的合成界面只作参考，不能自动当作产品原生UI凭据。

用户说“2+2交叉混合”时，实际选两篇借场景/叙事、另外两篇借构图/成果展示，按各自用途组合即可，不另填登记表。组合方法，重写任务与画面；不是拼四张原图，也不照搬教程、经历和数据。

### 3. 先准备能上图的成果

准备好输入、读者可复制的提示词与对应成果；[制作工作单](references/production-worksheet.md)仅在复杂任务需要时参考，不必填写或另存。每个重要要求都能在成品找到落点。

- 岗位雷达：岗位、来源链接、地点/薪资、匹配理由、缺口和优先级；重点展示能做决定的几行。
- 简历优化：同一段经历改前改后、对应JD要求、最终简历页面；不编经历和指标。
- PPT：打开的多页幻灯片及重点页，不以PPT下载卡代替成品。
- PDF/报告：正文、表格、结论或来源等可读局部，不只放封面或文件名。
- 旅行：路线、顺序、接驳和随身查阅内容，不能只放风景。
- 图像玩法：同一个对象的原图与新图，教程指令与效果对应。

成果先行指先决定读者能看见的内容，不意味着虚构一次实测。不把自制示意冒充搭子真实输出；引用真实结果不擅改数据和结论。

### 4. 写文案与分镜

读 [文案与画面](references/copy-and-visual.md)。封面用具体痛点、反差、欲望或可收藏成品形成强钩子；后面有实际结果兑现。正文自然提到**百度搭子＋具体动作＋成果用途**，Logo和话题不代替功能说明。

图中必须有可读的派活提示词。简单图片玩法可用“两张附件＋一句具体要求”，不硬凑四段；复杂任务再补材料、动作、关键条件和所需成品。长指令可拆重点，正文附完整可复制版。不要印幕后生图指令。

每页推动一个新问题：想要什么、怎么交代、得到什么、怎么判断/使用。页数随信息决定，不固定三/四/五张。内页不能重复同一张电脑/同一表格，只换标题。

同批各篇至少在构图上看得出区别，不能只换产品名和颜色。用户2026-09-17澄清：排版有区别即可，不强制完全不同的艺术风格。可用上下、斜向、上方一张大图＋下方三张小图；保留同主题和语气，改变主体大小、排列方向与阅读顺序。需要更大差异时再换媒介或叙事，不为差异硬塞MEME或人物。

上述历史排版意见不能替代2026-10-13图片改写验收：两版即使沿用同一构图，非真实UI的视觉也应明显不同，不再以极小位移或整页原图复用交付。

### 5. 生图、准确贴图、核验

用真实搭子操作截图与对应成品组织观看顺序，按参考选择适用构图和标注。不得AI生成使用场景、人物/道具或模拟操作画面；搭子实际生成的成果须能追溯到对应任务。

AI可辅助真实截图拼版，界面像素内容须保真，不能重绘提示词、控件或成果来模拟一次操作。控制单页字量，优先大幅可读界面；截图不适用、过时或文字不清时，换用合适素材或补采。

需要精确贴图时，按当前图像工具规则保留截图或等比嵌入准确组件；用户要求程序合成时可确定性排字。标题不拉伸，优先改换行与文字长度。图像编辑默认使用图像生成工具，不能擅自以Python重绘替代。保真策略见 [物料库](references/material-library-and-scene-generation.md)。

给读者的搭子指令放在正文或图中；后台拼版/编辑指令和局部修正不强制另存。把任务标题、附件缩略图/文件名、对话、输出卡和预览内容当作同一组核对；参考附件不能误放本次已生成的成果。所有操作引导词逐项与适用真实界面核对。

逐张看原尺寸，再看手机预览，按 [核验表](references/evidence-checks.md) 修复实际成图：

- 封面钩子有兑现，成果内容够大，提示词可读。
- 官方搭子Logo/物料和适用真实UI清楚出现，品牌、功能、状态正确。
- 人物、文件、数字、岗位、天数、条件与成果同一任务，没有旧内容残留。
- 控件与原始UI逐项对应，不增造参数、按钮或输入方式；小标题对应正文，分项之和对应总数，旅行地点对应画面和文案。发现错误定向改图并重看最终版本。
- 图文没有私信领取话术、制作口吻或错误产品事实；官号投放是官方演示/使用指引，无素人种草或虚构经历；其他用途的创作设定不当作普遍性能保证。
- 左上角没有图片序号徽标；行程DAY、任务步骤等内容标签可以有。
- 本篇内页有新信息；同批有明显构图差异；没有乱码、拉伸、遮挡或糊小字。
- 表达具体：适用场景、操作与成果清楚，删掉装饰与空泛夸赞后仍有可用信息；官号投放不以素人种草感为验收目标。

默认交付3:4竖图、有序图片、标题/正文/话题、可复制提示词、整组预览与ZIP。默认不附制作记录、来源台账和审核报告。用户只要求更新skill时不另生成笔记；不自动发布、外传私有素材或同步公开仓库。

## 维护

只有用户要求维护素材库或沉淀经验时才更新索引和审核学习；日常出稿不触发。素材缺失或库异常时再运行 `corpus.py verify`、`ui_materials.py verify`，禁止用AI图替代缺失原图。
