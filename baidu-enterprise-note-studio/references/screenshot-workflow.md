# 操作截图保护与合成

适用于用户明确说“图片里面的步骤截图不要动”。目标是改变外围画风，同时保留真实界面证据。

## 保护记录

每张记录原文件、页号、界面矩形 x/y/width/height、是否保持原位置和原尺寸。
本项目共享文件夹两张界面已按 1080 × 1440 最终画布记录：
- 添加成员：x=24，y=390，width=1029，height=664。
- 权限菜单：x=32，y=359，width=1025，height=654。

这些坐标仅适用于对应项目源图，新素材要重新测量。
保留红框、按钮名、原示例数据和原有清晰度。不能用 AI 重绘、补字或超分修复，再宣称“截图未改”。

## 实作顺序

1. 提取并保存原界面区域，无损 PNG。
2. 按最终画布确定外围标题、说明和装饰的可用位置。
3. 用内置 image_gen 生成所需位图。请求透明素材时核对 alpha，棋盘格印在 RGB 图上不算透明。
4. 正常字体排版。空间不够先改变换行和排版，不压扁标题。
5. 将原界面作为最后的图层贴回，避免被猫咪、边框或标注遮住。
6. 导出 PNG，从成图同坐标裁出保护区，去除 alpha 后比较 RGB 数组和尺寸。
7. 两区一致才记录“原像素保留”；不一致时检查缩放、重采样、色彩转换或遮挡来源。

可用 Node + sharp 实现无损合成和验证。验证比较解码后的像素，不比较两个 PNG 文件的整体字节；编码元数据不同不代表图像变化。若用户要求原尺寸不动，不能先缩放原截图再与缩放后的副本自证一致。

## 交付记录

保存最终图片、可编辑排版源、生成提示词、原截图来源与保护矩形、像素比较结果。
只给用户发布目录和简短制作说明；中间版本、失败透明素材、质量检测文件放工作目录。
原图模糊时保留它并如实注明来源限制，不能伪造高清 UI。若用户随后明确授权调整尺寸或遮蔽隐私，再按新授权执行并记录，不沿用“原像素一致”的说法。
